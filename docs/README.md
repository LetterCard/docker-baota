## 三十秒版本

```bash
cd baota-docker          # 仓库根目录（docker-compose.yml 就在这里）
docker compose up -d
docker compose logs -f baota  # 首次登录信息在这里
```

数据落在 `docker-compose.yml` 同级的 `data/` 目录里（业务 `data/www/`、面板状态
`data/panel/`、系统层 `data/system/`），删容器、重建、换镜像都不丢 ——
连面板里装的组件与插件都不用重装。
唯一硬要求：**持久化根必须在 ext4 / btrfs / xfs 上**（飞牛存储池就是，直接可用）。

更细的规则：**面板代码不持久化**（来自镜像，换镜像即升级面板；面板内点「更新」
不会生效 —— 执行入口守卫会把代码换回镜像版本）。见[持久化原理](persistence.md)。

## 三个必须先知道的约定

1. **`data/` 一个目录保住全部数据，三层分清楚**（业务 `data/www/`、面板状态
   `data/panel/`、系统层 `data/system/`；面板代码不在里面 —— 它属于镜像）。
   完整结构见[持久化原理](persistence.md#data-的目录模型与容器内路径一一对应)。
2. **不要在面板里点「更新」**：它不会生效（守卫会把代码换回镜像版本），
   换镜像标签才是升级路径（见[升级与迁移](upgrade.md)）。
3. **口令写在 compose 等于公开。** 镜像里没有任何固定口令，首次启动随机生成并
   打印到日志；既要固定又要保密请用同目录的 `.env`。

## 术语

| 词 | 含义 |
|---|---|
| **持久化层 / upper** | 系统层 upper 在 `data/system/<目录>`（只记录改动）；业务与面板状态是 bind 目录（`data/www/`、`data/panel/`），内容完整、容器销毁不丢 |
| **镜像层 / lower** | 镜像自带的同名目录，含**面板代码**。换镜像即更新系统配置与面板，你从没动过的文件自动跟着变 |
| **数据层（直通）** | `data/www/`（wwwroot 站点、backup 备份、server/data MySQL），内容完整、宿主机可直接读写，不走 overlay |
| **持久化根** | compose 挂进容器的 `data/` 卷（数据层 + 系统层都在里面），必须在 ext4 / btrfs / xfs 上 |
| **线 / 通道** | 一条跟进上游的发布流水线：`12_version`（稳定线 12.x）、`13_version`（最新正式版），均为手动发布；新增 14/15 只是加一行声明（见[发布流程](release.md)） |
| **面板代码 / 面板状态** | 代码 = `/www/server/panel` 本体（来自镜像，不持久化）；状态 = `data/panel/`（配置、插件、证书、面板设置） |
| **执行入口守卫** | `guard.sh` + `shim`：面板代码每次执行前先比对镜像版本，不一致就换回镜像副本 —— 面板内更新因此永不生效 |
| **降级** | 持久化没挂上或挂成只读。容器照常启动，但**写入会静默丢失**，健康检查会报 unhealthy |
